# Fishing Cat · 宝箱与鱼类收益系统方案

> 规划版本：v0.1.6；编写日期：2026-10-20。本文仅为方案，未实现钱包、宝箱实物、商店或存档迁移。
>
> “现状”依据当前 v0.1.5 源码核对；除明确标注现状的内容外，以下奖励、概率、价格、保底及界面均为**首期建议值，待实现与体验验证**。成功鱼数量的估算是数学参考，不是真人测试结果。

## 1. 目标与边界

保留轻量桌宠的短局节奏，让每次成功钓鱼有可积累的收益，让宝箱有实际内容，并通过图鉴和小型外观给满级后的玩家留下目标。闭环为：

```text
钓鱼 → 经验与图鉴记录 → 金币自动入账 → 自选基础外观
  └→ 尝试取箱 → 装饰碎片与图纸 → 自选进阶外观
```

- 当前 10 个角色继续全部直接可选，不把已有角色重新锁进商店或宝箱。
- 竹竿、纤维杆、秘银杆、传奇杆继续按现有等级免费解锁，不加金币或材料门槛。
- 首期只增加金币和装饰碎片两种可积累资源；图纸是永久解锁标记，不是第三种货币。
- 不增加地图、移动探索、鱼背包、手动卖鱼、体力、装备损耗、每日任务、限时外观或离线自动收益。
- 新外观只改变显示，不改变绿条、鱼速、经验、金币或宝箱概率。现有难度与经验曲线保持原规则。
- 不要求登录或联网；数据沿用本地存档。不会为了开箱扩大窗口或在桌面上强制弹窗。

## 2. 现有实现与缺口

### 2.1 已有鱼类收益

`fishing/catchMath.ts` 已计算品质、尺寸、售价和经验。品质售价倍率为普通 ×1、银 ×1.25、金 ×1.5、铱 ×2；当前鱼王售价固定 5000，不吃品质倍率。

**当前售价只是结算和图鉴中的展示值。** `fishing/data/SaveStore.ts` 的 `applyResult()` 更新经验、图鉴和统计，没有把 `price` 加入任何钱包。`SaveData` 没有金币、材料、外观购买、经济保底或奖励流水字段。不能把本次规划描述为“修复遗失金币”，也不能直接把历史显示价当作已经入账的资产。

普通鱼现价集中在 10～20，而鱼王为 5000。将这套显示价原样接入钱包，会让一次鱼王收入达到普通鱼的 250～500 倍，因此真实经济上线前须统一调整收益表和所有展示。

### 2.2 已有宝箱

| 环节 | 当前行为 |
|---|---|
| 出现 | 每次鱼类小游戏开始抽一次；基础 15%，MAX 抛竿 +15 个百分点，鱼竿另加 0/3/7/12 个百分点 |
| 概率范围示例 | 竹竿普通抛竿 15%；竹竿 MAX 30%；传奇杆 MAX 42% |
| 位置与时机 | 开局后 1～3 秒出现，在轨道高度 20%～80% 范围生成 |
| 取得 | 绿条覆盖时进度每秒 +0.8，离开时每秒 −0.6，达到 1 才算取得 |
| 成功条件 | 必须取得宝箱且最终钓到鱼，才以 `treasure=true` 结算 |
| 失败条件 | 鱼逃跑时箱一起丢失；鱼已钓到但箱进度没满，也不算取得宝箱 |
| 当前实际收益 | 该鱼经验 ×2.2、宝箱统计 +1、音效和 TREASURE 标记 |
| 尚未实现 | 箱内实物、金币或材料入账、图纸、保底、开箱奖励展示 |

垃圾不进入鱼类小游戏，也不抽箱。等待时提前收竿不生成结果；咬钩未及时响应属于逃跑。`ResultState.enter()` 立即调用统一结算入口，结果展示约 0.9 秒后才允许点击关闭；关闭结果不是领奖操作。

### 2.3 现有经验继续保留

```text
qualityXpIndex = 普通 0 / 银 1 / 金 2 / 铱 4
xp = (qualityXpIndex + 1) × 3 + floor(物种基础难度 / 3)
若取得宝箱：xp = floor(xp × 2.2)
若完美捕获：xp = floor(xp × 2.4)
若为鱼王：  xp = floor(xp × 5)
```

每步分别取整；首期增加宝箱实物时**保留现有 ×2.2 经验，只应用一次**，不再增加“开箱经验包”。逃跑 0 经验、垃圾默认 3 经验沿用现状。等级上限仍为 10，满级后经验可累计；不通过本期经济改造重调升级曲线。

物种收益使用鱼表中的基础难度，不使用本局随机心情、等级缩放后的有效难度，避免同一种鱼因为随机状态而产生难以解释的价格变化。

## 3. 鱼类收益：难度有回报，品质有价值

### 3.1 自动入账与建议价格

成功鱼自动折算金币，图鉴仍保留次数、最大尺寸和最佳品质；首期不保存可重复出售的鱼物品。结算将“售价”统一改为“鱼类收益”，展示金额必须与实际入账一致。

| 难度档 | 基础难度 D | 建议基础收益 B |
|---|---|---:|
| 轻松 | D ≤ 30 | 12 金币 |
| 熟悉 | 31～50 | 20 金币 |
| 挑战 | 51～75 | 32 金币 |
| 高难 | 76～99 | 44 金币 |
| 传说 | 鱼王；当前 D=110 | 80 金币 |

以上全部为建议值。当前 15 种鱼对应如下，方便实现时逐项核验：

| 鱼种 ID / 名称 | 当前基础难度 | 当前展示基价 | 建议基础收益 B |
|---|---:|---:|---:|
| carp / 鲤鱼 | 15 | 11 | 12 |
| herring / 鲱鱼 | 25 | 10 | 12 |
| anchovy / 凤尾鱼 | 30 | 20 | 12 |
| sunfish / 太阳鱼 | 30 | 12 | 12 |
| bream / 鲷鱼 | 35 | 20 | 20 |
| sea_cucumber / 海参 | 40 | 15 | 20 |
| walleye / 大眼梭鲈 | 45 | 11 | 20 |
| largemouth_bass / 大口鲈 | 50 | 20 | 20 |
| pike / 狗鱼 | 60 | 18 | 32 |
| tuna / 金枪鱼 | 70 | 20 | 32 |
| catfish / 鲶鱼 | 75 | 20 | 32 |
| squid / 鱿鱼 | 75 | 20 | 32 |
| pufferfish / 河豚 | 80 | 20 | 44 |
| octopus / 章鱼 | 95 | 20 | 44 |
| legend / 鱼王 | 110 | 5000 | 80 |

本表是面向首期经济的新建议，不改写历史结算。上线时 `fishTable`、图鉴基础收益、结算、钱包使用同一配置源，鱼王的旧 5000 彩蛋价一并更新，不能显示 5000 却只入账 80。

### 3.2 唯一结算公式

```text
M = 普通 1 / 银 1.25 / 金 1.5 / 铱 2
鱼类金币 = round(B × M)                 // 鱼王也使用品质倍率
首发现金币 = 本存档首次获得该物种时的 B，否则 0
本次金币 = 鱼类金币 + 首发现金币 + 宝箱金币
本次装饰碎片 = 宝箱碎片
```

- 首发现按物种 ID 只发一次，与当前角色、尺寸、品质无关；新纪录只展示记录，不再发可刷奖励。
- 全部 15 种鱼的首发现奖励合计为 424 金币，一次性发放，不参与长期单位收益估算。
- Perfect 通过已有品质提升间接提高金币，保留原经验倍率；不另乘金币倍率。注意现有规则下，基础普通品质即使 Perfect 也仍为普通。
- MAX 不直接乘金币；继续通过已有距离/品质、鱼池与宝箱概率规则体现价值。
- 尺寸不加金币倍率，避免把出条时长或极值尺寸变成额外经济乘区。
- 垃圾金币和材料均为 0，保留现有少量经验；逃跑、取消、未咬钩收竿均不产资源，不倒扣资源。

## 4. 宝箱首期：底奖、额外奖励与两层保底

### 4.1 保留获取操作，不把宝箱变成必拿任务

现有出现延迟、轨道位置、进度增减和“保住鱼才能保住箱”规则保持不变。玩家可以只追鱼；放弃箱不降低鱼类金币，也没有失败罚款。

成功取得箱时自动开箱，固定底奖为 **10 金币 +1 装饰碎片**，再抽一次额外奖励：

| 额外奖励 | 建议概率 | 本箱合计 |
|---|---:|---|
| 小金币包 | 60% | 20 金币 +1 碎片 |
| 碎片包 | 30% | 10 金币 +2 碎片 |
| 一张尚未解锁的装饰图纸 | 10% | 10 金币 +1 碎片 +1 张新图纸 |

不增加箱钥匙或等待倒计时。以上额外奖励只能抽一次，不提供广告、付费重抽或关闭重抽。

### 4.2 出现保底：连续 7 条成功鱼未取得箱，后续保证出现

新增 `successfulFishWithoutSecuredChest`，初值 0，上限 7：

1. 以“最终成功钓到鱼”为推进单位。成功鱼未取得箱，计数 +1；成功取得箱，计数归零。
2. 小游戏开始时，若计数为 7，本局直接安排箱出现；否则仍按现有 15%～42% 概率抽箱。
3. 保底出现的箱仍须用绿条取得。若玩家未取到箱但钓到鱼，计数保持 7，之后继续保证出现，直至拿到箱。
4. 逃跑、垃圾、提前收竿、拖动取消、程序重启均不推进，也不清零计数。已经取得箱但鱼逃跑时，没有任何箱奖励，计数维持本局开始前的值。

这是“最晚第 8 条成功鱼的机会必定出现箱”的保底，**不是保证第 8 条鱼必得奖励**。界面用“再成功钓到 N 条未取箱鱼后，宝箱必定出现”或“下次小游戏必定出现宝箱”，不能写“下条鱼必得宝箱”。不显示倒计时、不做强提醒。

保底状态跨重启保存；随机种子与本次捕获 ID 绑定。故意逃跑不会加速保底，重启不会清除已有进度或重抽已确定的箱内容。

### 4.3 图纸保底：最多 6 个已取得箱获得一张新图纸

首期只有第 5 节的 3 张进阶图纸。随机图纸从尚未拥有的图纸中等概率选择，不重复发已拥有图纸。

- 新增 `openedChestsWithoutNewBlueprint`，初值 0，上限 5。
- 已取得箱开出金币/碎片时计数 +1；开出一张新图纸时归零。
- 计数为 5 且仍有未拥有图纸时，下一只已取得箱的额外奖励强制为新图纸，替代该次随机额外奖励；固定底奖照发。
- 购买“定向研究”获得图纸也将该计数归零，使“距上次获得新图纸”口径一致；研究价格和确认界面须说明。
- 逃跑、出现但未取得箱，不算开箱，不影响图纸保底。
- 3 张图纸全部拥有后停用图纸保底，原 10% 图纸结果改为额外 +2 碎片；此时对应箱共 10 金币 +3 碎片，箱永不变空。

因此从零图纸开始，最多 18 个已取得箱能解锁全部 3 张图纸；这不包括玩家主动放弃或鱼逃跑的箱，也不是 18 次抛竿保证全收集。定向研究可绕过随机等待，休闲玩家不必追每只箱。

## 5. 资源用途与外观循环

### 5.1 首期固定目录

以下名称、外观和价格均为建议，需按 `设计规范.md` 与 `design/` 形成像素资产后验收。使用统一外观目录，购买前可预览；所有角色可使用，不重新售卖已有角色。

| 外观 | 获取方式 / 建议成本 | 展示范围 |
|---|---|---|
| 星星徽章 | 120 金币 | 人物旁的小型静态徽章 |
| 草叶帽饰 | 180 金币 | 独立挂件槽，逐角色适配位置 |
| 藤纹竿皮肤 | 240 金币 | 当前已装备鱼竿的纯配色皮肤 |
| 荷叶挂件 | 对应图纸 +120 金币 +4 碎片 | 挂件槽 |
| 流萤底环 | 对应图纸 +180 金币 +6 碎片 | 低亮度、低频像素底环 |
| 月纹竿皮肤 | 对应图纸 +240 金币 +8 碎片 | 当前鱼竿的纯外观皮肤 |

图纸通过箱获得，也可在同一外观页对任一指定未拥有图纸执行“定向研究”，每张 **240 金币 +6 碎片**，直接解锁指定图纸；制作费用另计，并在确认页同时显示。图纸永久拥有，不因制作而消耗。每项外观只制作一次，不能重复扣费。

基础外观合计 540 金币，进阶制作合计 540 金币 +18 碎片。若 3 张图纸均来自箱，全部 6 项外观需 1080 金币 +18 碎片；若全部定向研究，需 1800 金币 +36 碎片。

装备/卸下不消耗资源；已购买外观不绑定当前角色。首期采用挂件、竿皮肤、底环三个槽，同槽只能选一项；角色切换时不丢失选择。帽饰等跨角色适配不合格时先延期该外观，不能靠重叠贴图交付。可在设置关闭动态外观效果。

### 5.2 养成、图鉴、外观各自承担的目标

- 经验和等级：提供短中期成长，继续自动解锁现有功能竿。
- 图鉴：首次发现获得一次性奖励，品质与尺寸纪录支撑长期自选挑战；全收集展示纪念标记，不把核心功能锁在全收集后面。
- 金币：每条成功鱼都有贡献，用来直接购买或制作自己喜欢的外观。
- 装饰碎片：让取得箱有稳定价值，通过制作与定向研究消耗；不另设按天解锁的材料。
- 图纸：提供开箱惊喜，保底与定向研究共同限制运气成本；不是付费抽奖池。

满级以后仍可推进图鉴与外观，不增加无限等级。全部外观收齐后允许金币、碎片继续积累；首期接受有限内容自然结束，不通过强制维修、不断涨价或资源衰减制造消耗。

## 6. 收益期望、节奏与通胀控制

### 6.1 计算口径

按当前鱼表生成权重、忽略捕获失败及抛竿对鱼池分布的影响，建议基础收益的加权均值为 `2264 / 109.4 ≈ 20.69`，即 **20.69 金币/条成功鱼**；若假设品质均值倍率为 1.25，鱼类收入约 **25.87 金币/条**。这些只是统一比较的假设，不等于真实新手或高手收入。

若每次出现的箱都能保住，且将鱼类成功率对出箱分布的影响忽略，出现概率为 p 时，在第 8 次机会强制出现下：

```text
平均两次取得箱之间的成功鱼数 = (1 - (1-p)^8) / p
p=0.15 → 约 4.85 条；p=0.42 → 约 2.35 条
```

真实玩家会放弃箱或逃鱼，实际取箱频率会更低；不能将上述频率直接写成产品承诺。

尚有未解锁图纸、计入六箱图纸保底时，一张新图纸平均约需 `(1 - 0.9^6) / 0.1 ≈ 4.69` 个已取得箱；三张约 14.06 箱。此阶段每箱平均约 15.24 金币、1.26 碎片，且附新图纸机会。图纸全齐后每箱平均 16 金币、1.5 碎片。期望包含建议掉落表，不包含鱼本身或首发现奖励。

### 6.2 建议体验目标

按每条成功鱼合计 **约 30 金币** 的简化比较口径，暂不算首发现奖励（参考鱼类约 25.87、宝箱再贡献少量金币）：

| 目标 | 纯金币参考 | 额外限制 |
|---|---:|---|
| 首件星星徽章 | 约 4 条成功鱼 | 无材料、无图纸 |
| 任一基础外观 | 约 4～8 条 | 玩家自选 |
| 三件基础外观全齐 | 约 18 条 | 不要求开箱 |
| 全部六件的金币成本 | 约 36 条 | 进阶还需图纸与 18 碎片 |
| 全部图纸均定向研究时的金币成本 | 约 60 条 | 共需 36 碎片，通常由材料节奏主导 |

作为低位参考，若仍有图纸未获得、每次箱都能保住，竹竿非 MAX 每 4.85 条成功鱼取得一个箱，积累 18 碎片约需 69 条成功鱼；传奇杆 MAX 的同条件参考约 34 条。真实数值受箱取得率、图纸先后和材料消耗影响，应在实测后调整。只希望买几件基础外观的玩家无需完成这条长线。

不把目标写成“每天必须玩几分钟”。实现后按新手、一般、熟练三档记录成功鱼数/失败数/取箱率/品质分布与资源来源，验证基础首饰能快速获得、进阶外观有选择空间。只修改配置值，不同时重调难度与经济，避免无法判断效果来源。

### 6.3 防止收益失控

- 鱼王基础收益从历史展示价 5000 调为建议 80，品质上限 160；首发现再加 80。它仍有稀有纪念性，不成为一次击穿外观目录的提款机。
- 金币只有一个品质倍率；Perfect、MAX、尺寸、宝箱不会叠出额外金币乘区。宝箱金额独立列项，不能乘到整次收入上。
- 不售卖收益倍率、出箱率、体力或高效付费角色；外观价格不随等级、资产或游玩天数增长。
- 不设可出售图纸或外观的回收价，防购买/回收循环；素材不得跨存档交易，首期无玩家市场。
- 新增鱼种与外观前重算长期期望。首发现、迁移礼包必须与可持续收益分开统计。
- 金币和材料用非负安全整数保存，校验非法值与溢出；不通过每天清零或过期控制存量。

## 7. 结算示例与对账

以下均使用本方案建议收益，经验仍按现有代码计算。

| 场景 | 金币明细 | 材料 / 图纸 | 经验 |
|---|---|---|---:|
| 新手首次钓到普通鲤鱼，非完美，无箱 | 鱼 12 +首发现 12 = **24** | 无 | `3+floor(15/3)` = **8** |
| 已收集章鱼，铱品质、Perfect、取得箱；箱额外抽中金币包 | 鱼 `44×2=88` +箱底奖 10 +额外 10 = **108** | **1 碎片** | `46→floor(46×2.2)=101→floor(101×2.4)` = **242** |
| 首次鱼王，基础银经 Perfect 升为金，无箱 | 鱼 `80×1.5=120` +首发现 80 = **200** | 无 | `45→floor(45×2.4)=108→108×5` = **540** |
| 已有 5 个箱未出新图纸，本次成功取箱并保住鱼 | 在鱼类收入外再加 **10** | **1 碎片 +1 张未拥有图纸** | 该鱼正常应用一次宝箱 ×2.2，无额外开箱经验 |

结算中的“本次金币”须能逐项相加得到钱包增量。首发现只奖励金币，不再额外乘经验。鱼类品质、宝箱是否取得、是否首次发现都以最终已提交的同一结果为准。

## 8. 开箱与界面呈现

### 8.1 原结果页内完成

继续使用现有 340×390 窗口与像素羊皮纸结算面板。鱼名、品质、尺寸、经验保持主层级，下面增加最多三行可读收益：

```text
鱼类收益          +88 金币
宝箱              +20 金币 · +1 装饰碎片
本次合计          +108 金币
```

首次发现时增加“首次发现 +B 金币”，新图纸时显示图标、完整名称及“已解锁制作”。内容较多时将首发现并入鱼类收益说明、图纸作为宝箱下方一行；仍放不下时仅该奖励区域内部滚动，不挤占菜单按钮或缩小全文字号。

箱已取得时，结算面板内播放约 0.6 秒的开盖与少量像素星光，结果明细直接可读。沿用现有宝箱音效，避免新增长旋律与升级音效重叠；升级反馈继续遵守已有延后播放规则。静音有效，关闭动态效果时直接呈现静态打开箱图标。

自动开箱与入账不依赖动画结束或第二次点击。结果达到现有可关闭时机后，点击继续不会少奖；提前打开菜单、切换形象或隐藏窗口也不重复结算。不增加必须逐个点击的掉落物。

### 8.2 菜单与图鉴

- 菜单头部仅加紧凑的金币/碎片余额入口，打开统一“外观”页；不在空闲桌宠旁常驻大钱包。
- 外观目录明确显示“可购买 / 可制作 / 缺图纸 / 材料不足 / 已拥有 / 已装备”。不足时显示准确差额，禁用重复购买。
- 预览必须与实际穿戴一致，确认只用于花费；免费装备/卸下即点即生效。
- 图鉴显示建议基础收益、四品质倍率和首发现是否已领取；显示已拥有图纸与保底进度的地方集中在外观页，不挤压小游戏。
- 菜单按钮、面板滚动、外部点击关闭沿用当前交互；按钮再次点击关闭当前面板，钱包入口与列表元素不得遮挡原 32×32 热区。
- 渲染扩展须同步原生窗口可见像素/交互 region；透明空白继续穿透，面板打开时保持整窗交互。

## 9. 数据与一次性结算

### 9.1 建议存档扩展

沿用 localStorage key `fishing-codex-save-v1`、产品 identifier 和顶层 `version:1`，增加可选 `economy` 子对象，其内部独立 `schema:1`。不要直接把顶层版本改为 2：当前加载逻辑遇到非 1 会返回默认存档。

建议字段如下，仅为数据设计，不是已实现的类型：

```text
economy:
  schema: 1
  coins: 非负整数
  decorFragments: 非负整数
  ownedCosmetics: 外观 ID 列表
  equippedCosmetics: 挂件 / 竿皮肤 / 底环 ID，可空
  unlockedBlueprints: 图纸 ID 列表
  firstDiscoveryClaimed: 已处理首发现奖励的物种 ID 列表
  pity:
    successfulFishWithoutSecuredChest: 0..7
    openedChestsWithoutNewBlueprint: 0..5
  nextCatchSeq: 单调递增的捕获序号
  lastAppliedCatchSeq: 最后已提交结果序号
  pendingCatch: 捕获序号与奖励随机种子，可空
  pendingSettlement: 完整待提交结果与奖励明细，可空
  recentReceipts: 最近 32 次结果/购买摘要，用于本地对账
  migrationId: 固定迁移标记，可空
```

已有经验、鱼竿、角色、音乐、图鉴与统计保持兼容。图鉴和 `firstDiscoveryClaimed` 的更新必须由同一结算生成，不根据结果页的 NEW 动画反推奖励。状态校验须去重 ID、夹紧保底计数、拒绝 NaN/负数，未知外观 ID 不生效但不应导致整个旧存档重置。

### 9.2 事务与幂等

1. 实际抛竿时为本次分配并持久化 `catchSeq` 与奖励种子；取消与逃跑不会增加经济收益或保底。重启中断局按取消处理，不在恢复时模拟补发一条成功鱼。
2. 成功鱼结算时，根据现有图鉴、保底和奖励种子生成唯一明细，包括图纸选择、首发现、金币、碎片、经验和统计变化。
3. 先把不可重抽的完整 `pendingSettlement` 写入同一存档；再构造新快照，一次 `setItem` 提交全部余额、图鉴、经验、统计、保底与已应用序号，更新本次升级免费解锁的鱼竿，并清空 pending。两次写入之间不得先加经验或先发箱物品。
4. 已提交的序号不得重复应用；只能结算当前 pending 捕获。关闭结果、重复进入状态、迟到回调均只读取同一收据。购买同样在一个快照内完成“验证拥有与余额→扣费→解锁”。
5. 重启发现完整待提交结果时，按原内容补交一次，不重抽；已完成提交时只显示收据。未形成完整结果的中断钓鱼不发奖励。
6. 持久化失败时不宣称“已到账”。保留内存中的原结果供重试，显示轻量“本次进度尚未保存，点击重试”状态；禁止通过重开结果重新抽奖。若用户在存储始终失败时退出，未落盘数据可能丢失，应如实显示状态。

当前 `SaveStore.save()` 静默吞掉失败且不返回状态，不能直接承担该承诺；实现期必须改为可观察的提交结果，并用草稿快照保证失败不会留下半笔内存扣费。此处需要事务完整性，不需要联网反作弊或复杂经济服务器。

## 10. 旧存档迁移

首次读取无 `economy` 的有效旧存档时，生成经济子对象并一次写回：

- 新存档金币/碎片为 0；旧存档有经验、抛竿记录或已收集鱼种任一进度时，发固定欢迎包 **120 金币 +3 碎片**，并写入固定 `migrationId`，只发一次。
- 旧图鉴已有物种加入 `firstDiscoveryClaimed`，不再次给这些鱼发首发现金币；升级后的首次新物种正常领取。
- 不按旧捕获次数 ×5000 或当前价格回算金币。旧版本没有真实钱包与明细，回算会虚构历史资产并放大早期鱼王彩蛋价。
- 保底计数从 0 开始，不根据旧箱统计补抽。原宝箱经验、统计、图鉴及免费鱼竿解锁全部保留。
- 角色选择与全角色可选状态、已选音乐/本地音乐 ID、自启、隐身设置保持不变；不改应用 identifier 或存储位置。
- 迁移失败时保留原始存档，报告未保存状态，重试仍使用同一欢迎包事务；不能先发包后遗漏迁移标记。
- 覆盖已有经济存档时不重复迁移。完整存档备份与跨设备复制按同一存档处理；首期不承诺防止用户主动回滚自己备份。

旧存档的首次奖励标记采用“已记录即已处理”，欢迎包作为新系统欢迎礼，说明口径与新玩家不同。不要声称这是等额补发历史卖鱼收入。

## 11. 实施分期

| 阶段 | 范围 | 完成标准 |
|---|---|---|
| A：收益地基 | 统一建议价格；经济子对象迁移；金币、首次发现、一次性事务与收据；结果明细 | 每次成功鱼实际入账且可对账；旧存档不丢进度；无空的商店承诺 |
| B：可用首期 | 宝箱底奖/额外奖、两层保底；3 基础外观与3 进阶外观；预览、研究、制作、穿戴；存档异常提示 | 玩家能从钓鱼走完至少一条完整购买与一条制作路径；全部10角色与4功能竿可正常使用 |
| C：体验与平衡 | 三档实测、不同 DPI/输入/重启、按来源统计收益，配置微调 | 文档建议值替换为经验证值，并记录改动依据；不同时重调物理难度 |
| 后续候选 | 增加纯外观、图鉴纪念册、可选主题 | 依据实际使用需求再评估，不在首期暗埋任务/在线账号/大世界依赖 |

A 为内部开发检查点；面向用户的首期发布须完成 A+B 与必要的 C 验证。单独上线无用途的余额或只有“敬请期待”的商店不能算闭环交付。本规划不授权直接改变当前发布包，也不表示上述系统已完成。
