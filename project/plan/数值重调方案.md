## 1. 问题结论（一句话）

当前小游戏在数值上**「打不输」**——无头模拟 15 条鱼 × Lv0/5/10 各 200 次，捕获率全表 **100%**，等级、鱼难度、心情浮动在玩家手上完全不可见。根因是「绿条太大 + 难度天花板封死 + 等级/竿反向加成」，必须把难度真实传导到玩家。

### 根因链
| # | 根因 | 证据 |
|---|---|---|
| 1 | 绿条占轨道 35%（200/568），鱼几乎永远泡在条里 | 渲染 ≈39px，鱼判定盒仅 8 单位 |
| 2 | `DIFF_MAX=115` 封顶，鱼王(110)在 Lv0 就撞顶，等级再高也无法更难 | 等级只把绿条撑大 → 反而更容易 |
| 3 | `BAR_SIZE_PER_LEVEL=2.5` + 竿 `barBonus` 最高 22，Lv10+传说竿共 +44，反杀难度缩放 | 模拟里 Lv10 钓鱼王比 Lv0 更稳 |
| 4 | 行为系数 dart 0.65 / sinker 1.15 差距过大，「难度数字」不预言挑战 | 同难度 dart 明显比 sinker 易（扫描实证） |
| 5 | `PROGRESS_GAIN=0.075` 太慢，小游戏 17–30s，对桌宠偏长 | 时长统计 |

## 2. ⚠️ 关键耦合（开发 agent 必读，否则会复活老 bug）

`src/renderer/render/PetView.ts:371-372`：
```ts
const fishW = 22
const fishH = 33
ctx.drawImage(s.fishIcon, ..., fishW, fishH)   // 小游戏鱼图标固定 22×33px
```
绿条渲染高度 = `BAR_SIZE × scale`，其中 `scale = BAR_H/TRACK_H ≈ 0.194`（`constants.ts:45` 注释，TRACK_H=568）。

- 当前 `BAR_SIZE_BASE=200` → 渲染 ≈39px > 鱼 33px → 绿条盖得住鱼 ✅
- 若直接把 `BAR_SIZE_BASE` 缩到 110（≈21px）< 鱼 33px → **绿条比鱼小、鱼沉底时盖不住**（这正是 2026-10-16 从 108 提到 200 修复的 bug）

**结论**：缩小绿条前，**必须同步缩小小游戏鱼图标**，让「小绿条 ≥ 小鱼的渲染高度」。这是本次重调的支点改动（纯渲染，无逻辑风险）。

## 3. 推荐改动清单（按文件分组）

### 3.1 渲染支点：`src/renderer/render/PetView.ts`
| 行 | 现值 | 推荐值 | 说明 |
|---|---|---|---|
| 371 `fishW` | 22 | **16** | 鱼图标缩到 ~16×24，给小绿条让出空间 |
| 372 `fishH` | 33 | **24** | 渲染 24px；绿条基准 120×0.194≈23px ≈ 鱼，居中可盖、移动时鱼会探出上下沿=产生挑战 |
| 374 `crown` | `fishY - 25` | 随 `fishH` 微调（如 `fishY - 20`） | 鱼王皇冠跟随新鱼高，避免悬空 |

> 仅改这两行的绘制尺寸常量即可，鱼图标源图 `fishIcon` 不动（等比缩放绘制）。

### 3.2 核心：`src/renderer/shared/constants.ts`（`T` 对象）
| 行 | 参数 | 现值 | 推荐值 | rationale |
|---|---|---|---|---|
| 50 | `BAR_SIZE_BASE` | 200 | **120** | 渲染 ~23px（配缩小后的鱼 24px），让「出条」真能发生；原 200 致全表 100% |
| 52 | `BAR_SIZE_PER_LEVEL` | 2.5 | **1.0** | 等级加成别再反杀难度缩放（Lv10 仅 +10，而非 +25） |
| 54 | `BAR_SIZE_MAX` | 250 | **165** | 配合基准封顶，避免好竿+高等级把条撑回过大 |
| 59 | `DIFF_MAX` | 115 | **160** ⚠️见注 | 抬高难度天花板，让 Lv10 鱼王仍比 Lv0 难（修复反向变易）。**此值未经模拟，见第 6 节必须重跑 balance** |
| 75 | `SINKER_ACCEL` | 52 | **30** | 现版 sinker 贴墙太凶难追，压平到与 floater 同级 |
| 76 | `FLOATER_ACCEL` | 52 | **30** | 同上 |
| 80 | `PROGRESS_GAIN` | 0.075 | **0.11** | 把单局时长从 17–30s 压回 ~10–15s（涨更快，但鱼更难跟） |
| 104 | `BITE_MIN_MS` | 700 | **600** | 咬钩等待压缩（桌宠节奏） |
| 105 | `BITE_MAX_MS` | 8000 | **4000** | 桌宠 0.7–8s 空等偏长，压到 0.6–4s；配合 `BITE_LEVEL_FACTOR` Lv10 上限 ~1.5s |

> 注：`DIFF_MAX` 若暂不改动（保留 115），则 Lv10 鱼王仍会因「难度封顶 + 绿条变大」轻微反向变易——这是已知残留。建议**同批改到 160** 一并解决；若 playtest 显示 160 使低难鱼过易，回退到 115 并改由「鱼 AI 更激进」兜底（见第 5 节）。

### 3.3 鱼行为系数：`src/renderer/fishing/entities/Fish.ts`
`BEHAVIOR_INTERVAL` 映射（行 8–13）：
| 行为 | 现值 | 推荐值 | 说明 |
|---|---|---|---|
| `dart` | 0.65 | **0.8** | 抬高，让 dart 不再「白给」 |

## 4. 预期效果（模拟验证的梯度方向）

基于复刻物理的无头模拟（复刻 `Fish`/`CatchBar`/`ProgressBar` + 近似人类鼠标策略，绿条基准 110–120、DIFF_MAX 115），Lv0 熟练档捕获率呈干净单调梯度：

| 鱼（难度·行为） | 现值 | 推荐后（Lv0 熟练） |
|---|---|---|
| 鲤鱼 (15·mixed) | 100% | ~100% |
| 大口鲈 (50·mixed) | 100% | ~85% |
| 鲶鱼 (60·sinker) | 100% | ~75% |
| 章鱼 (95·sinker) | 100% | ~70% |
| 鱼王 (110·mixed) | 100% | ~53% |

新手档（不熟练鼠标）同步整体下沉；**等级轴**（Lv0→Lv10，配合 DIFF_MAX=160）应使同种鱼捕获率下降、鱼王在 Lv10 明显更难。这些是 `[PLACEHOLDER]`，以真机为准。

## 5. 备选兜底（若 DIFF_MAX=160 让低难鱼过易）

不要回头放大绿条。改走「鱼 AI 更激进」：
- `FISH_SPEED_MAX`: 158 → 185
- `DART_AMP_MAX`: 150 → 175
- `DART_INTERVAL_FRANTIC`: 230 → 180（高难鱼变向更频）

保持绿条小、手感由鱼制造——符合「难度交给鱼」的设计意图。

## 6. 开发 agent 改完必做验证（不验证 = 盲改）

1. **修模拟盲点**：`scripts/difficulty-sim.ts`（或 `npm run run-balance`，见 `test/` 文档）当前用的是 `BAR_SIZE_BASE` 而非 `barSizeForLevel`，且人类策略理想，对平衡问题**失明**（只会报 100%）。改为驱动真实 `FishingController` 并调用 `barSizeForLevel(level, rodBonus)`，确认梯度出现后再信数据。
2. **跑量化**：`node scripts/run-balance.mjs`（或等价），确认：
   - 鲤鱼 Lv0 ≥ 90%，鱼王 Lv0 < 60%
   - 鱼王 Lv10 捕获率 < 鱼王 Lv0（等级轴不反向）
3. **编译/单测**：`npm run typecheck` + `npm test`（gesture/overlay 24 条）必须全过。
4. **真机 playtest 失败信号**（任一即回退调参）：
   - 鱼王 Lv0 胜率 > 70% → 绿条仍过大（先查 `PetView` 鱼图标是否真缩到 24px）
   - 鲤鱼 Lv0 胜率 < 90% → 绿条过小，回调 `BAR_SIZE_BASE` 到 130–140
   - 单局平均 > 15s → `PROGRESS_GAIN` 不够，提到 0.13
   - Lv10 鱼王比 Lv0 更易 → `DIFF_MAX` 没生效或 `BAR_SIZE_PER_LEVEL` 仍过大
