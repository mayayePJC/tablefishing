# Fishing Cat · 像素风设计规范

> 本文档是项目**全部视觉内容的唯一基准**：人物、鱼、道具、UI、图鉴、Logo。
> 后续新增或修改任何视觉资产，必须先读本文档，按对应章节的规范与自检清单执行。
> 代码实现以仓库为准；本文档回答"**应该长什么样、为什么、怎么验收**"。
> 配套文档：`plan/PRD.md`（交互与技术约定）、`design/README.md`（当前设计索引及版本要求）。

---

## 0. 风格总纲（一句话定调）

**星露谷（Stardew Valley）式像素风**：温暖、明亮、手工感、可爱、高可读。

四个关键词的含义（验收时逐条对照）：

| 关键词 | 判断标准 |
|---|---|
| 温暖 | 色相偏黄绿/土色系，避免纯灰与冷蓝滥用；角色有肤色腮红感 |
| 明亮 | 明度阶梯清晰，每件资产在深/浅背景下都"跳"得出来 |
| 手工感 | 硬边缘、整数像素、可见的像素排布；禁止抗锯齿、禁止渐变模糊 |
| 可爱 | 比例头身比约 1:2～1:2.5，眼睛占面部 1/4 以上，姿态有夸张 |

**风格红线（任何资产不得违反）**：
1. 全部图形画在整数网格上，`imageSmoothingEnabled = false` / `image-rendering: pixelated`，**永不抗锯齿**。
2. 所有悬浮在透明桌面的元素（人物、鱼、浮标、水花、钓线、UI）必须带 `#241a12` 暗描边或深色衬底——桌宠窗口透明，资产必须在任意壁纸上可见。这是硬约束，来自用户多次实测反馈。
3. 单精灵色数上限：角色 16~32 色；小鱼/道具 8~16 色。色越多越显脏，宁缺毋滥。
4. 不画写实、不画 3D 感、不用照片素材、不用 AI 生成的中间调图片直接入游戏（AI 图仅可作概念参考，须按本文档网格重绘为像素资产）。

## 1. 调色板规范（Palette）

### 1.1 唯一色源
所有颜色必须来自 `src/renderer/render/Palette.ts` 的 `PAL` 对象或其派生（`mixHex` 明度混合）。**禁止在绘制代码里散落裸 hex**——散落的 hex 是当前"粗糙感"的来源之一（同色系出现微小米差，整体发脏）。

### 1.2 现有色板角色划分
- **环境**：sky 三阶 / water 三阶+foam / grass 三阶 / sand 两阶 / wood 三阶
- **角色**：skin 两阶 / hair 两阶 / shirt / pants / boot
- **UI**：uiBorder / bar 系列（barFill, barFillDark, barEdge, barHighlight）/ track 两阶 / progress 三阶（低红 #d64545、中黄 #e8c53a、高绿 #5fd45f）
- **品质**：normal #c8ccd4 / silver #dfe8f0 / gold #ffd23f / iridium #7ec8f0
- **通用描边**：INK = OUT = `#241a12`（暖深棕黑，禁止用纯黑 #000000 描边——纯黑在暖色系里显脏）

### 1.3 新增颜色规则
新增任何颜色（新形象的配色、新鱼的配色）必须满足：

1. **三阶明度阶梯**：每个主色必须同时定义 base / shade（base 混黑 25~30%）/ light（base 混白 20~30%）三阶，命名加 `_D` / `_L` 后缀（对齐现有 `SHIRT_D/SHIRT_L` 约定）。只有一阶的颜色不许上场——平色是"糙"的第一大来源。
2. **色相聚拢**：同一形象的主色相不超过 2 个（含点缀色），整体偏向暖或偏冷二选一，不混搭。
3. **饱和度纪律**：主色饱和度 25~65%；只有强调元素（MAX 蓄力、传说鱼、星星）可用 >80% 高饱和。
4. 新色先加进 `PAL` 或角色私有常量区（SpriteFactory 顶部），并写清注释。

## 2. 精灵图规范 · 人物（24×40，七姿态）

### 2.1 网格与站位（硬约束）
- 画布 **24 宽 × 40 高**（`PLAYER_W/H`），脚底贴 y=40，头顶留 0~2px。
- 屏幕显示缩放 `PLAYER_SCALE = 2.6` → 约 62×104 px；站位 `PLAYER_X 238 / FOOT_Y 342`（窗口 340×390 内，人物靠右，钓线向左抛）。
- **人物一律面朝左**（池塘在左），持竿手在画面左侧。
- 躯干占网格中段，头约占上 1/3；头身比约 1:2（可爱向，不走写实比例）。

### 2.2 七姿态定义（`PlayerPose`）
| 姿态 | 用途 | 画面要求 |
|---|---|---|
| idle0 | 待机主帧 | 标准站立，竿斜持，眼睛睁开 |
| idle1 | 待机眨眼帧 | 仅眼睛变化（闭眼/横线），**其他像素与 idle0 完全一致**，保证闪烁不跳戏 |
| cast0 | 抛竿引杆 | 竿向后（右上）扬起，手臂后拉，身体微后仰 |
| cast1 | 抛竿过渡 | 竿回正到顶点，手臂前送 |
| cast2 | 抛竿出线 | 竿向左下指，竿尖最低——**钓线从这一帧的竿尖出发** |
| reel | 收线 | 竿向左下、手臂屈肘做拉的动作，竿尖略低于 cast2 |
| show | 举鱼展示 | 双手（或双鳍/双袖）举鱼过头，鱼在头顶偏左；竿斜靠身侧右侧 |

### 2.3 绘制顺序（统一，保证遮挡关系正确）
1. 身后件：尾巴、桶、袍摆下摆等
2. 腿/脚 → 躯干 → 头 → 帽/耳/头发
3. 手臂 + 钓竿（最后画，永远在最上层）
4. `blk()` 统一暗描边（先画 OUT 扩 1px，再画填充）——除极小点缀（睫毛、瞳孔）外一律描边。

### 2.4 竿尖偏移表（`ROD_TIPS`）
每个形象一张 `Record<PlayerPose, [x, y]>`，坐标 = 竿尖相对精灵左上角。**改竿的角度 = 改这张表 + 对应姿态的 `rodLine` 起点/终点**。验收：cast2/reel 两帧的竿尖，与 `PetView.rodTipWorld()` 实际拉出的钓线起点重合，不允许"线从空气中长出来"。

### 2.5 人物验收清单
- [ ] 闭眼剪影测试：把角色涂黑，轮廓仍能认出是"谁"（剪影差异化是 5 形象不雷同的底线）
- [ ] 7 姿态并排看，idle0/idle1 只差眼睛；cast0→cast2 有清晰的"引—送—指"动作弧线
- [ ] 全身外轮廓 1px 暗描边连续无断点（透明背景可见性）
- [ ] 色数 ≤32；每个主色有 _D/_L 两阶
- [ ] 头顶留白 ≤2px，脚底不超出 y=40
- [ ] 钓鱼线/浮标/lev 徽章不被人物遮挡（徽章在人物右上角外侧）

## 3. 精灵图规范 · 鱼（12×8 基座）

### 3.1 基座与身型
- 基础画布 **12×8，头朝右**；`rotate90` 生成朝上/朝下两帧上图鉴与小游戏。
- 四种身型（`FishBodyShape`）：
  - `spindle` 纺锤（常规鱼）：椭圆 5×2.6 + 三角尾 + 背鳍
  - `long` 长条（鲱鱼/鱿鱼）：椭圆 4.5×1.7，双尾鳍
  - `round` 圆球（河豚/章鱼）：椭圆 3.5×3，四向小刺
  - `flat` 侧扁（鲷鱼）：近圆 3.2×3.2，无背鳍
- 每条鱼的结构件：主色身（`color`）+ 辅色鳍尾（`color2`）+ 肚皮亮条（主色混白 35%）+ 1px 眼（INK）+ 背部暗带（主色混黑 35%，透明度 0.4~0.5）。

### 3.2 差异化要求（当前最短板的改进点）
仅靠"椭圆+三角尾+换色"会让 15 种鱼看起来像同一条鱼染了不同颜色。**每条鱼至少有一个识别性细节**，按物种真实特征取 1~2 个：
- 鲤鱼：须（嘴侧 2 根 1px 线）；太阳鱼：鳃盖红点+纵纹
- 金枪鱼：背鳍高耸+腹部银带；狗鱼：尖长吻+背靠后
- 鱿鱼：腕足（下缘 3 根短须）；章鱼：圆头+腕足；河豚：满刺
- 鱼王（legend）：体型最大 + 王冠 + 金橙配色 + 红眼

### 3.3 鱼验收清单
- [ ] 12×8 内画完，不溢出不裁切
- [ ] 三色阶齐全（身/肚皮/暗带）之外，鱼眼必须 1px 纯暗——鱼眼是"活"的关键
- [ ] 旋转两帧后头朝上/朝下均不变形、不出现 1px 断裂
- [ ] 15 条并排：3 米外能分清至少 80% 的鱼（剪影/配色/细节三选其一达到）

## 5. UI 规范

### 5.1 小游戏（收线捕获条）
- 轨道：`BAR_W 34 × BAR_H 110`，位于 `(16, 236)`（人物左侧平行，不挂屏角）。
- 外框：`PAL.ink / wood / woodLight` 整像素木框，统一图鉴与结算风格；不加模糊辉光。
- 轨道背景：`trackTop→trackBottom` 四档水色色阶 + 水中微粒（12 个 2×2 半透明点）。
- 绿条：`barEdge` 外扩 2px → `barFill` 主体 → 顶部 2px `barHighlight` 高光 → 底部 2px `barFillDark` 阴影。**绿条必须灵活**（手感参数见 PRD/constants，视觉只负责"亮、弹、有高光"）。
- 进度条：轨道右侧 14px 宽，低/中/高三段变色 + 顶部 2px 白色反光。
- 鱼图标：16×24 显示，在绿条上层绘制，夹在轨道内；传说鱼加王冠，连王冠一起限制边界。
- 宝箱：32×25 显示 + 独立小进度条，两者作为整体限制在轨道内。零/满进度均不得越框。

### 5.2 结算弹窗（星露谷对话框语言）
- 米色背板 `PAL.paper` + 木棕边框、木色标题栏和右下硬边投影。
- 宽 232，先计算名称/奖励/解锁行数，再确定高度；关闭按钮和页脚始终有独立空间。
- 文字：`rtext()` 矢量中文——整数对齐、`textBaseline: middle`、行高固定、**1px 级深棕细描边 `rgba(40,28,16,0.5)`**（衬底不抢字）。标题 16px / 正文 12~13px / 脚注 11px。
- 结构（钓到鱼）：整数倍鱼图标（左）| 名称 16px + 尺寸 + 品质三星（右）→ 售价/品质 → 可换行 MAX CAST / PERFECT / TREASURE → XP/升级 → 解锁新竿 → 独立页脚。NEW 留在标题栏右侧。
- 星星：在透明离屏画布对 `star` 使用 `source-in` 染品质色，再画到主画布；禁止在不透明面板上直接染色，避免星形变方块。

### 5.3 lev 徽章
- 紧贴人物右上角（跟随 `playerX/FOOT_Y` 计算，不钉屏幕角）。
- `LV{level}` 像素字 + 自适应经验条（`barFill` + 顶部白光），按文字实际宽度分配空间；右侧保留 3px 窗口边距。
- `PAL.uiBacking` 暖深底与木色边，保证壁纸可读。

### 5.4 工具按钮
- 右下 `(318, 368)`，r=12 圆形；汉堡三横线；暖暗底、浅纸色边，悬停态金边。
- 像素风落位：圆是唯一允许的非像素几何形（触达面积优先），内部图标保持硬边。

### 5.5 面板（HTML/CSS 层：三个图鉴 + 说明）
- 面板：三个独立图鉴，宽 248px；帮助宽 296px。统一羊皮纸、木棕边框与硬边投影，顶部 12px 落位，底部预留工具按钮，内容内部滚动。
- 标题 15px、关闭按钮 28×28，同一边距和分隔线；正文深棕色，菜单 12px、卡片辅助字 10px。
- 卡片：角色 48×80（2×）、鱼 36×24（3×）、竿 36×36（3×），全部 `image-rendering: pixelated`；名称和状态独立排版。
- 选中态：深木边 + 内金线 + “使用中”；锁定态保留文字对比度，仅图标灰度化，标明解锁等级。
- 一级菜单 112px、设置列 188px；BGM 位于一级菜单并打开独立音乐面板，设置二级菜单不承载曲目列表，禁止三级级联。

## 6. 图鉴规范（三大图鉴 = 数据驱动，加内容不改 UI）

| 图鉴 | 数据源 | 卡片内容 | 解锁态 |
|---|---|---|---|
| 形象图鉴 | `shared/characters.ts` `CHARACTER_LIST` | 待机帧预览 + 名称 + 使用中，简介悬停显示 | 全部可选 |
| 钓鱼竿图鉴 | `shared/rods.ts` `ROD_LIST` | 彩色竿图标 + 名称 + 控鱼加成/属性条 + 使用/等级状态 | 未解锁：图标灰度 + "Lv.X 解锁"，升级后打开即刷新 |
| 鱼图鉴 | `fishing/data/fishTable.ts` `FISH_TABLE` | 同源 12×8 横向鱼图 + 名称 + 基础售价，悬停显示捕获次数/最大尺寸 | 未捕获：鱼影 + "？？？"，不透露鱼名 |

规则：
1. 预览图一律用**真实游戏内精灵烘焙**（`SpriteFactory.build` / `buildRodIcon` / `buildFish` 的 `toDataURL()`），禁止另画一套"图鉴专用图"——两套图必然漂移。
2. 新增鱼 = 只在 `fishTable.ts` 加一条数据；新竿 = `ROD_LIST` 加一条；新形象 = 改 4 处（见 §7）。
3. 品质标签文字用 `QUALITY_LABEL`，颜色用 `QUALITY_COLOR`，不手写。

## 7. 新增内容标准作业流程（SOP）

### 7.1 加一条新鱼
1. `fishTable.ts` 加一项：`id/name/nameEn/difficulty(15~110)/behavior/minSize/maxSize/color/color2/body/weight`。
2. 选身型：四种 `body` 里挑最接近的；都不像 → 先按 §3.2 想清楚识别性细节，再决定是否值得加第 5 种身型（加身型要同步改 `FishBodyShape` 与 `drawFishBody`）。
3. 配色遵守 §1.3（两色 + 派生三阶在绘制时 mixHex 生成）。
4. 自检：过 §3.3 清单 + 跑 `npm run typecheck` + `petshot` 截图目检。
5. 图鉴自动生效，无需改 UI。

### 7.2 加一个新人物形象
固定改 4 处（缺一不可，来自现有约定）：
1. `shared/types.ts`：`CharacterSkin` 联合类型加值；
2. `shared/characters.ts`：`CHARACTER_LIST` 加项（name + desc，desc ≤12 字）；
3. `render/SpriteFactory.ts`：新增 `drawXxxCharacter(pose)` 函数（照 §2 网格与七姿态）+ 一组私有配色常量（三阶命名）；
4. `render/SpriteFactory.ts`：`ROD_TIP_XXX` 偏移表 + 登记进 `ROD_TIPS`，`build()` 路由加分号。
自检：过 §2.5 全清单；5 形象待机帧并排，剪影两两不同；竿尖与钓线起点对齐。

### 7.3 加一根新竿
`rods.ts` `ROD_LIST` 加一项（`color` 会直接上图鉴图标）。其余自动。

### 7.4 改任何精灵后
必跑：`npm run typecheck` → `npm test`（若碰了 gesture/overlayClose 相关不涉及，可跳过说明）→ `scripts/petshot.ts` 出 PNG 目检 → `npm run tauri:build` 确认打包。

## 8. 粗糙感诊断与对策（当前资产的已知问题清单）

按优先级排列的升级项（即"变好"的具体含义，逐项完成后在本章销项）：

### P0 — 人物（最影响第一印象）
1. **剪影同质化**：5 形象都是"方块躯干 + 方块头"堆叠，3 米外轮廓相似。
   → 对策：每个形象放大一个剪影特征——猫（尾+耳+盔）、蛙（宽体+桶+护目镜外凸）、企鹅（圆滚+围巾飘带）、巫师（尖帽+袍摆外撇）、农夫（标准人形作基准）。允许肢体略微超出 24×40 中心区，但不得超出画布。
2. **cast 三帧动作差太小**：目前主要靠竿角度变化，手臂/身体参与不够。
   → 对策：cast0 手臂后拉+躯干后倾 1px、cast1 回正、cast2 前倾指竿，三帧重心连成弧线。
   ✅ **已修复（2026-10-19 晚）**：cast0 后仰(+1)+马步+双臂后拉+竿向后（右上）扬起；cast1 双臂前送+竿回正到顶点（近垂直）；cast2 前倾(-1)+左臂前下指+竿向左下尖最低。钓竿改八邻域暗描边长竿，五形象同步落实（握点随姿态移动），petshot 七姿态对比表 + 钓线起点场景目检通过。
3. **色阶太平**：不少大色块只有 base 一阶。
